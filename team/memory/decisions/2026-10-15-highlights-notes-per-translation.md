# Ruling: Highlights and notes are per-translation (2026-10-15)

Founder, Oct 15, 2026: "Your highlights and notes save in what
translation you are in. If you switch translations it will change your
notes and highlights to a fresh view of that translation then when you
switch back it will load all your highlights and notes from that
translation"

- Highlights and notes are stored PER TRANSLATION (text edition).
  Switching translations swaps the visible set; switching back restores
  it exactly. No cross-translation anchoring or mapping.
- This supersedes run 4's translation-independent keying for both
  highlights and notes, and it dissolves run 10's offset fork: a span's
  character offsets always render against the translation it was made
  in.
- Migration rule for pre-run-10 data (no translation recorded): assign
  to the translation active at upgrade; no duplication.
- Canon dormancy (founder clarification, Oct 15, 2026): tradition is
  never a data scope. A highlight/note shows iff the current translation
  matches its set AND its book is in the current tradition's canon.
  Otherwise it is dormant: stored untouched, invisible, restored
  exactly when both conditions hold again (e.g. New Testament notes
  under Jewish mode, deuterocanon notes under Protestant mode).
